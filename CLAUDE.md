# Eatery

A marketplace for home-cooked food: hosts open seats at their table ("Table") or sell homemade
food for pickup ("Market"); guests book in the app. Two clients on one Supabase project: the
Vite web app in `src/` and the native iOS/Android app in `mobile/` (Expo).

> Workspace rules in `~/Documents/AgentWorkspace` already apply. Do not restate them here.
> This file is only for what is true about *this* repo and nowhere else.

## Stack

- Web: Vite + React 18 + Tailwind + zustand, deployed by Vercel on push (`vercel.json`).
- Native: `mobile/` — Expo SDK 58, React Native 0.88, Expo Router (typed routes), React Compiler,
  MapLibre (OpenFreeMap tiles, no key), Stripe PaymentSheet, Expo push. `mobile/AGENTS.md` is
  Expo's own guidance for this SDK — read it before touching any Expo API.
- Server: Supabase project `pgbyxglxpcckvygtlhgo` ("Eatery", Seoul), in the apieschacong@unal.edu.co
  organization since 2026-11-24 (Andresinp is a Developer there; free plan, 2 active projects). SQL in `supabase/migrations/`,
  Edge Functions in `supabase/functions/` (shared code in `_shared/`).

## Commands

```bash
npm install && npm run build                     # web (root)
cd mobile && npm install
npm run ios | npm run android                    # dev build on simulator/emulator (not Expo Go)
npm run verify                                   # typecheck + lint + i18n + unit tests + DB tests
npm run check:env                                # build gate: public config is real-shaped
sh supabase/tests/db-test.sh                     # throwaway local Postgres, every migration, assertions
cd supabase/functions && deno check --node-modules-dir=none <fn>/index.ts
```

`db-test.sh` needs Homebrew `postgresql@17` (no Docker). `supabase/tests/bootstrap.sql` stands in
for Supabase's `auth`/`storage`; it is never applied to a real project.

## Layout

- `mobile/src/lib/api.ts` is the only place the app talks to Supabase (plus `auth.ts`,
  `realtime.ts`). Column lists there must match the grants in migration 0006.
- `mobile/app.config.js` reads public config **by name** from the root `.env` (`VITE_SUPABASE_*`,
  `VITE_STRIPE_PUBLISHABLE_KEY`) — one source for both clients. Optional `EXPO_PUBLIC_GOOGLE_*`,
  `EXPO_PUBLIC_EAS_PROJECT_ID` turn on Google sign-in and push.
- i18n: `mobile/src/i18n/locales/<lang>/<area>.json`, flat keys, English is the reference;
  `src/i18n/resources.ts` imports them (`scripts/i18n-check.mjs` enforces parity).
- `ios/` and `android/` under `mobile/` are generated by `expo prebuild` — never hand-edit.

## Constraints that are easy to get wrong

- **Bookings are created by the server only.** `stripe-webhook` calls `server_create_order` when
  the deposit is paid (atomic seat decrement, idempotent per payment intent); free listings use
  `book_free_listing`. Clients cannot insert or update `orders`. Never reintroduce a client insert:
  before 0006 a guest could write a "confirmed" order with any deposit.
- **The price is computed in one place**, `public.quote_booking`, in the listing's own currency.
  `listings.currency` stores the display prefix ("€", "₺", "CHF"); `private.currency_iso` maps it.
- **Private columns:** `profiles.email`, `dietary_prefs`, `allergen_exclusions` and
  `listings.exact_address` are not selectable by clients. Own profile via `my_profile()`; address
  via `listing_address()` (host and booked guests only). `select('*')` on those tables fails.
- **Cancelling a listing with bookings goes through `cancel-listing`** (refunds each guest); the
  database refuses a direct status change (`guard_listing_cancel`).
- **Deploy coupling.** Web deploys on push. Migrations and Edge Functions deploy by hand
  (`supabase db push`, `supabase functions deploy <name>`) — committing changes nothing live.
  Phones run old builds for months: migrations add, never rename or drop.
- **Live schema drift:** the live project had columns no migration created (`listings.currency`).
  0006 is guarded to apply on top of it; diff the live schema before pushing anything new.
- **Payments are Stripe, not In-App Purchase:** meals eaten and food picked up in person are
  physical goods/services (App Store 3.1.5(a)). Never sell anything digital in the app.
- **Bundle id `com.andresinp.eatery`**, store name "Eatery: Home Dining". Fixed from the first upload.
- Store copy and in-app strings never name the other platform (guideline 2.3.10); the i18n check
  fails the build on it.
